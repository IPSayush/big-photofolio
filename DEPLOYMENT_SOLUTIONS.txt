[2] ERROR 1: VERCEL BUILD FAILURE (No workspaces found)
================================================================================

ERROR DETAILS:
--------------
npm error No workspaces found:
npm error   --workspace=packages/client
Error: Command "npm run build --workspace=packages/client" exited with 1

KYU AAYA (ROOT CAUSE):
----------------------
1. NPM Workspaces Syntax Mismatch:
   NPM CLI me jab `--workspace` flag use kiya jata hai, to NPM package ka exact "name" 
   (jo packages/client/package.json me "@photofolio/client" hai) expect karta hai, 
   na ki folder ka path ("packages/client").
   Pehle vercel.json me build command "npm run build --workspace=packages/client" likha tha. 
   Jab Vercel ne ye command chalayi, to NPM ko "packages/client" naam ka workspace nahi mila 
   aur build 1 exit code ke saath fail ho gaya.

2. Root Directory Setting Issue on Vercel:
   Agar Vercel project settings me "Root Directory" ko "packages/client" set kiya gaya ho, 
   to us directory ke andar koi "workspaces" define nahi hoti. Wahan `--workspace` flag 
   chalane par NPM turant "No workspaces found" error throw kar deta hai.

3. Root package.json me build script missing tha:
   Root package.json me pehle seedha "build" script nahi tha, sirf dev scripts the.

KAISE THIK KAREIN (SOLUTION):
-----------------------------
1. Code Repo me already fix kiya gaya hai:
   - Root package.json me standard build script add kiya:
     "build": "cd packages/client && npx vite build"
   - vercel.json me buildCommand ko simple "npm run build" set kiya gaya hai.
2. Vercel Dashboard me setting ensure karein:
   - Vercel Project Settings -> General -> Root Directory ko hamesha "./" (Project Root) hi rakhein. 
   - Root Directory ko "packages/client" ya "packages/server" mat karein.


================================================================================
[3] ERROR 2: ARCHITECTURE CONFUSION (2 Alag-Alag Projects Banana)
================================================================================

KYU PROBLEM HAI (ROOT CAUSE):
-----------------------------
1. Vercel ek Serverless platform hai, traditional VPS nahi:
   Vercel par normal Express server (jo node server.js se port 5000 par 24/7 listen karta hai) 
   direct nahi chalta. Vercel par backend ko Serverless Function ke roop me chalana hota hai.

2. Is project ka architecture Single Unified Fullstack Project hai:
   - Frontend: packages/client/dist (Vercel CDN se static files serve karta hai).
   - Backend API: api/index.js (Express app ko Vercel Serverless Function me wrap karta hai).
   - vercel.json me rewrites configured hain:
     * /api/(.*)  -> Backend serverless function (api/index.js)
     * /(.*)      -> Frontend React SPA (index.html)

3. Agar aapne Vercel par 2 alag projects banaye hain:
   - Backend project fail ho jayega kyunki Vercel ko koi HTML/Frontend output nahi milega.
   - Frontend project me /api calls fail hongi (404 Not Found) kyunki frontend relative 
     URL ("/api/...") call karta hai aur backend dusre domain/project par hoga.

KAISE THIK KAREIN (SOLUTION):
-----------------------------
- Vercel par Backend aur Frontend ke 2 alag-alag projects MAT banayein.
- Vercel par SIRF 1 SINGLE PROJECT import karein (Repo Root se).
- Vercel automatically Frontend build karega aur /api routes ko Serverless Function 
  bana dega. Dono ek hi domain par chalenge aur CORS ki koi problem nahi aayegi.

[4] ERROR 3: MONGODB ATLAS IP WHITELIST & CONNECTION FAILURE
================================================================================

ERROR DETAILS:
--------------
MongoServerSelectionError: Could not connect to any servers in your MongoDB Atlas cluster.
One common reason is that you're trying to access the database from an IP that isn't whitelisted.

KYU AAYA (ROOT CAUSE):
----------------------
1. MongoDB Atlas Security Firewall:
   Atlas by default unhi requests ko allow karta hai jinka IP address Network Access whitelist me ho.
2. Local Machine:
   Jab aapka local ISP ya WiFi reconnect hota hai, to public IP change ho jata hai. Agar wo IP 
   Atlas me added nahi hai, to local backend start hone par crash ho jayega.
3. Vercel Deployment:
   Vercel ke Serverless Functions dynamic AWS cloud IPs se run hote hain jo har request me badal 
   sakte hain. Agar Atlas me "0.0.0.0/0" allow nahi hai, to Vercel par deploy hone ke baad har 
   API call database connection timeout / 500 Internal Server Error degi.

KAISE THIK KAREIN (STEP-BY-STEP SOLUTION):
------------------------------------------
1. MongoDB Atlas dashboard (https://cloud.mongodb.com) par login karein.
2. Left sidebar me "Security" ke andar "Network Access" par click karein.
3. "Add IP Address" button dabayein.
4. "ALLOW ACCESS FROM ANYWHERE" option par click karein (ye "0.0.0.0/0" enter kar dega).
5. "Confirm" par click karein.
6. Check karein ki connection URI me database name ("photofolio") shamil ho:
   mongodb+srv://<username>:<password>@cluster.mongodb.net/photofolio?retryWrites=true&w=majority

[5] ERROR 4: VERCEL PAR MISSING ENVIRONMENT VARIABLES
================================================================================

KYU ERROR AAYEGA (ROOT CAUSE):
------------------------------
Local system par .env file hoti hai, lekin .env file security reasons ki wajah se 
Git repo me push nahi hoti (.gitignore me hoti hai).
Backend me packages/server/src/config/env.js startup par validate karta hai:
  - MONGODB_URI
  - JWT_ACCESS_SECRET
  - JWT_REFRESH_SECRET

Agar Vercel ke Project Settings me ye environment variables add nahi kiye gaye, to jaise hi 
koi user API call karega, Vercel function crash ho jayega:
"Missing required environment variables: MONGODB_URI, JWT_ACCESS_SECRET, JWT_REFRESH_SECRET"

KAISE THIK KAREIN (STEP-BY-STEP SOLUTION):
------------------------------------------
1. Vercel Dashboard me apne project me jayein.
2. "Settings" tab -> "Environment Variables" par click karein.
3. Niche diye gaye variables add karein:
   - MONGODB_URI = <Aapka MongoDB Atlas connection string>
   - JWT_ACCESS_SECRET = <Aapka JWT access token secret key>
   - JWT_REFRESH_SECRET = <Aapka JWT refresh token secret key>
   - NODE_ENV = production
   - AWS_ACCESS_KEY_ID = <Aapka AWS key, agar S3 use ho raha hai>
   - AWS_SECRET_ACCESS_KEY = <Aapka AWS secret, agar S3 use ho raha hai>
   - AWS_REGION = ap-south-1
   - S3_BUCKET_NAME = <Aapka S3 bucket name>
4. Save karne ke baad "Deployments" tab me jakar "Redeploy" karein.
